Permission groups and how Elevate uses them
Permission group What Elevate uses it for
Read access 5 Graph scopes Show your profile, eligible roles and PIM requirements.
PIM write access 2 Graph scopes Activate and deactivate Entra roles and PIM group access.
Azure access 1 Azure scope Find Azure resources and manage your role activations.
Access packages 1 Graph scope Find, request and cancel self-service access.

Consent does not make you an admin. PIM activation requirements still apply.

The risk to manage

Write scopes are powerful. A compromised app or token could misuse your access, with greater impact for admins. Use trusted builds, a protected device and minimal access.

Before your first activation

Quickest: the shared Elevate app, an optional multi-tenant registration the project provides so you can try Elevate without creating one. It has no SLA and may change or be withdrawn, and an administrator grants consent once per tenant.

For control over scopes, redirect URIs and lifetime, use your own or your company’s app registration. Azure CLI or Azure PowerShell sign-in needs neither, but supports Azure resource roles only.
