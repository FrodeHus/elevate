Design canvas

Elevate for Windows

The Windows 11 counterpart of the macOS menu bar app: a tray flyout that behaves like the Wi-Fi and Quick Settings flyouts, plus five small windows. Everything follows Fluent 2 (Mica, 4 px controls, Segoe UI Variable) so it feels like part of the system rather than a port. The mockups below are set in the viewer's theme; switch your theme to see the other one.

1. The flyout

Left-click on the tray icon opens a 380 px flyout anchored above the taskbar, near the icon. It hides on deactivation. The structure matches the macOS panel one to one: pivots per role kind with activation counts, a pinned Active now group, and one group per tenant with the account row carrying the sign-in method caption.

What to notice
  1. Pivots carry counts. The Windows tab strip is a SelectorBar with an accent underline; the count pill is filled when non-zero, outlined when zero. Same numbers as the macOS tabs.
  2. Group headers pin. Active now and each tenant are ListView groups, so the header stays put while the list scrolls. The account row is the group header and carries the sign-in caption, exactly like the folded single-tenant layout on macOS.
  3. One prominent action per row. Activate (or Request, when the policy needs an approver) is the accent-filled button; Deactivate stays a quiet standard button and is disabled for the first five minutes with a tooltip. Extend appears beside the countdown during the last 15 minutes.
  4. Policy notes under the name. "approval", "MFA" and "Conditional Access" come straight from the PIM policy (approval setting, MFA enablement rule, authentication-context rule), with a tooltip explaining each; users know before pressing anything whether a step-up or an approver is coming.
  5. Countdown is tabular. Segoe UI Variable has tabular figures; the countdown never jitters. Under ten minutes it turns to the warning colour and bold.
  6. The tray icon is the app icon's double chevron as a monochrome 16 px glyph with the active count beside it, matching the macOS menu bar item.

Single and bulk activation share one window. Duration is a ComboBox in 30-minute steps capped at the policy maximum, the reason is remembered per user, and ticket fields appear only when the policy demands them.

Behaviour
  • Progress in place. When Activate is pressed the Status column shows a ring per row, then Active, Pending approval, or the server error text. The window stays open until every row has settled.
  • Reason field is prefilled with the last reason and validated to the policy's minimum length before the button enables.
  • Bulk grouping is by tenant; roles in the same tenant run sequentially, tenants in parallel, exactly like the macOS coordinator.
  • Approval rows show the warning pill so the user knows before pressing the button that the role will not be active immediately.

Azure resources pivot
  • Each row is a scope path and a role name, with suggestions from the tenant's role definitions once a scope resolves.
  • The scope shows the resource display name as a caption after validation, so /subscriptions/…/resourceGroups/rg-prod becomes "rg-prod · Contoso Production".
  • Manual roles get the default policy of one hour, eight hours max, reason required, and are marked "Manual" in the flyout row caption.
